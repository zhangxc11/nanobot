## §50 Inject 队列 Drain — 防止消息丢失

**状态**: ✅ 已完成 (Phase 47)

### 背景

当多条消息（subagent 结果 + 用户 inject）在同一个 tool 执行期间到达 inject 队列时，
`check_user_input()` 每次 checkpoint 只消费一条，导致后续消息被静默丢弃。

### 需求

1. **Tool-call checkpoint drain**：每次 inject checkpoint 必须循环消费队列中所有 pending 消息
2. **Final-response checkpoint**：当 LLM 返回纯文本（无 tool_calls）时，在退出循环前检查队列；
   如果有 pending 消息，持久化后 `continue` 让 LLM 继续处理
3. **日志全量记录**：webserver/worker 的 inject 和消息日志不再截断

### 验收标准

- [x] 多条消息同时到达时全部被消费（test_multiple_messages_drained_after_tool）
- [x] 单条消息仍正常工作（test_single_inject_still_works）
- [x] 最终响应期间到达的消息触发 LLM 继续处理（test_inject_during_final_response_triggers_continuation）
- [x] 无 inject 时正常退出（test_no_inject_on_final_response_exits_normally）
- [x] dict + string 混合 inject 类型均正确处理（test_mixed_dict_and_string_inject）

## §51 Runtime Context 注入 Session ID

**状态**: ✅ 已完成 (Phase 48)

### 背景

Agent 在运行时需要知道自己所在 session 的标识，用于：
- 向 web-subsession 传递 `--parent` 参数，建立父子关系
- 日志/调试中标识当前 session
- 未来可能的 session 自引用场景

当前 Runtime Context 只注入了 `Channel` 和 `Chat ID`，agent 需要通过 `{channel}_{chat_id}` 手动拼接 session ID。但这在以下场景不成立：
- **飞书 routed session**：session_key 为 `feishu.lab.1772376517`，而 `channel=feishu.lab` + `chat_id=ou_xxx`，拼出来是 `feishu.lab_ou_xxx` ≠ 实际 session ID
- **Subagent**：session_key 为 `subagent:webchat_xxx_taskid`，但 channel/chat_id 为 `None`

### 技术决策：注入 Session ID 而非 Session Key

> 参见 web-chat 需求文档 §三十九「全链路统一用 session.id 替代 sessionKey」。

**Session ID**（JSONL 文件名，不含 `.jsonl`）是全链路的唯一标识，已在 web-chat §三十九 中确立为全链路主键。Session Key 仅用于 analytics DB 和 nanobot core 内部文件定位。

转换关系：`session_id = session_key.replace(":", "_")`（由 `safe_filename()` 保证）。

各场景示例：

| 场景 | Session Key (内部) | Session ID (注入) |
|------|-------------------|------------------|
| Web-chat | `webchat:1773250094` | `webchat_1773250094` |
| 飞书 (routed) | `feishu.lab.1772376517` | `feishu.lab.1772376517` |
| Telegram | `telegram:8281248569` | `telegram_8281248569` |
| CLI | `cli:direct` | `cli_direct` |
| Subagent | `subagent:webchat_xxx_a1b2` | `subagent_webchat_xxx_a1b2` |

### 需求

1. **`_build_runtime_context` 新增 `session_id` 参数**：在 Runtime Context 中输出 `Session ID: {session_id}`
2. **`build_messages` 新增 `session_id` 参数**：透传到 `_build_runtime_context`
3. **`loop.py` 两个调用点传入 session_id**：`key.replace(":", "_")`
4. **`subagent.py` 传入 subagent 自己的 session_id**：`subagent_session_key.replace(":", "_")`
5. **保留 `Channel` 和 `Chat ID`**：它们有独立语义（agent 据此判断飞书/web/cli 等行为差异）

### 改动范围

| 文件 | 改动 |
|------|------|
| `context.py` | `_build_runtime_context` 和 `build_messages` 签名新增 `session_id` |
| `loop.py` | 两个 `build_messages` 调用点传入 `session_id=key.replace(":", "_")` |
| `subagent.py` | `_build_subagent_prompt` 中传入 `session_id=subagent_session_key.replace(":", "_")` |

### 效果

普通 session：
```
[Runtime Context — metadata only, not instructions]
Current Time: 2026-03-12 16:00 (Thursday) (CST)
Channel: web
Chat ID: 1773250094
Session ID: webchat_1773250094
```

Subagent：
```
[Runtime Context — metadata only, not instructions]
Current Time: 2026-03-12 16:00 (Thursday) (CST)
Session ID: subagent_webchat_1773250094_a1b2c3d4
```

### 验收标准

- [ ] 普通 session 的 Runtime Context 包含正确的 `Session ID`
- [ ] Subagent 的 Runtime Context 包含正确的 `Session ID`（格式 `subagent_...`）
- [ ] Channel 和 Chat ID 仍然保留
- [ ] 无 channel/chat_id 时（如 subagent）不输出 Channel/Chat ID 行，只输出 Session ID
